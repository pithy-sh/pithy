New package: `@pithy-sh/vector` — semantic search over your own content, in your own Cloudflare account. Workers AI embeds, Vectorize indexes, and D1 keeps the text, because Vectorize returns ids and scores rather than content and caps metadata at 10 KiB. What this adds over calling the binding yourself is the metadata half, which Vectorize makes a provisioning-time decision wearing the costume of a query-time one: a filter on a field indexed after its vectors were written does not error, it silently returns a short result set, and there are only ten metadata indexes per index. So an index declares its filterable metadata once, in Zod. That declaration provisions the metadata indexes, types the filter builder, refuses a filter on an unmarked field at runtime, and is reconciled against the live index by `pithy vector provision` — which waits for each metadata index to go live before anything writes a vector, since Cloudflare applies them asynchronously. `provision` then records what it observed as the per-environment `VECTOR_PROVISIONED` var, and the Worker compares its declarations against that record at boot: mark a field filterable, deploy without re-provisioning, and you get `vector/metadata_index_drift` naming the field and the command instead of quietly short results. Offline, by design — reading an index's metadata indexes is a control-plane call, and an account API token has no business on the request path of a search. It proves the config declares nothing provisioning did not see the last time it ran, which is exactly the case that bites. A provisioned index the config does not declare is a leftover, not a fault, and does not stop a boot. The embedding model is pinned per index and used for writes and queries alike, so a corpus cannot be built in one space and searched in another. Every ceiling Vectorize publishes is checked before the call, with a `vector/*` code naming the limit. A write lands in D1 before it reaches the index and stamps its model only on acceptance, so a half-failed write self-heals; a delete leaves the index first, so nothing matches that cannot be hydrated. `pithy vector reprocess` re-embeds what a model change left behind, through a Workflow with keyset paging that resumes where it stopped; `pithy vector reset` rebuilds an index from the corpus, behind the same confirmation gate `pithy seed --redo` uses. Routes are auth-gated by a copied `requireAuth()`, so a project without `@pithy-sh/auth` denies rather than opens.

Five defects in the Paddle rail's sweep and webhook, two of them money and two of them credentials.

**The sweep could never project a refund, and it poisoned the webhook's second chance.** `sweepPaddleEvents` asks Paddle for `adjustment.created` and `adjustment.updated`, and the adjustment map needs the transaction to tell a full refund from a partial one. The reader was optional and the sweep never passed one, so every swept adjustment answered "this deployment cannot read the transaction" — and recorded itself as handled, which made the webhook redelivery of the same `event_id` a duplicate the guard skipped. The sweep did not merely miss the refund; it stopped the webhook from catching it. The sweep now builds the reader from its own credentials and transport, so a caller cannot forget what it is never asked for, and the map refuses a caller that supplies none rather than degrading into a wrong answer.

**A failed event was never retried.** The sweep set `processedAt` even when it wrote an error, and freshness is read off `processedAt` — so the next sweep counted the failure a duplicate, advanced the cursor past it, and no pass ever looked again. Halting the cursor in front of a failure only ever bought a second look that the row itself then refused. A failure now leaves `processedAt` null beside its error, which is the package's own drift signal.

**A full refund delivered as two partial adjustments never revoked.** Full-versus-partial compared one adjustment's own total against the transaction's grand total, and Paddle raises an adjustment per refund: 99.00 refunded in two goes is two approved adjustments of 49.50, both partial, no revoke, and a fully refunded customer keeping what they bought. The comparison is now against every approved refund and chargeback against the transaction, summed — read with `include=adjustments`, merged by id so the adjustment in hand counts whether or not Paddle's include has caught up with it.

**The webhook persisted whatever it was sent.** Any event type outside the transaction, subscription and adjustment sets was stored whole, and nothing in the schema narrows an unknown body. A destination subscribed to `client_token.*` therefore wrote a live client token into `pithy_payments_webhook_events` — Paddle redacts an api key's `key` and does not redact a client token's `token`. An event type this build does not act on is now recorded as its envelope alone: id, type, and when.

**The sweep's `event_type` filter used an undocumented wire form.** It sent the key repeated. Paddle documents one key with comma-separated values for every `array[string]` parameter, verified against the live API. More to the point, the filter was the only thing keeping credential-bearing events out of D1, and a query parameter is a request honored by someone else's service. The form is now the documented one, and the sweep additionally records nothing outside the list it asked for — so an unhonoured filter costs a wasted page rather than a token in a table.

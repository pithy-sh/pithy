A command about one environment composes each Worker for that environment. `pithy migrate --env`, `pithy upgrade --env` and `pithy deploy --env`'s pending count evaluated `pithy.config.ts` with `compositionEnvironment()` answering `undefined`, so a config whose migrations differ by environment was counted and migrated with the wrong set. `pithy feature destroy` composed for none while `pithy provision --feature` composed for `feature`, so a capability a config composes for deployed environments alone was provisioned and never torn down, its Secrets Store entries included; it now composes for `feature` too. `pithy token` derives CI permissions from `--env`'s composition, and whether `pithy deploy --env` and `pithy secrets --env` record an audit row is answered from that environment's. They, `pithy provision`, `pithy dashboard connect` and `pithy dev` now compose through one primitive, `project/composeFor.ts`, which stamps `ENVIRONMENT`, re-reads a config this run already evaluated for another environment, and restores what it found. `pithy remove --drop --env` reverses the migrations of that environment's composition; it reversed those of a composition for none, carried out of the Worker picker `pithy add`, `ui` and `worker sync` share, which now composes for the environment its caller names.

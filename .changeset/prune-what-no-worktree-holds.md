`pithy feature prune` frees the port blocks of features whose worktree and branch are both gone. `feature destroy` frees a block, but only from inside the worktree, so a worktree removed any other way — `git worktree prune`, a teardown script of your own, a directory deleted by hand — stranded its block, and the sweep of deleted checkouts never reached it, because the checkout it is filed under was still there. A block is freed only when its worktree's directory is gone from disk and its branch no longer exists locally: a branch that exists keeps it, checked out or not, and so does a directory on disk that has it checked out, pins it in a `.dev.config.json` — read at the worktree's root and at the project's place in it, for a project in a subdirectory — or is its `.worktrees/<issue>-<slug>`, registered with git or not. A `local:<path>` key is freed once its path is gone, and a `heads/<branch>` key is read as the branch a same-named tag shadows. The checkout it runs from is never freed, and no other checkout's blocks are judged. The worktree listing is read NUL-separated. It frees under the registry lock in one read-modify-write, and refuses outside a git repository, in a bare repository's worktree or a submodule, whose registry key other repositories can share, and when a `.dev.config.json` will not parse. The reclaim that rebuilds a lost registry, in `pithy dev`, `feature create` and `feature sync`, keeps exactly the blocks prune keeps, through the same predicate. `--dry-run` reads without the lock and writes nothing; `--json` carries `command`, `root`, `dryRun` and `freedBlocks`. `pithy doctor` marks the same blocks `← no worktree; pithy feature prune`, and its `--json` entries carry `orphaned`, decided by the function the command frees by. Allocation does not run it for you.
